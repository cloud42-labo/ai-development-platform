## 第1条 目的

本規程は、OwnerまたはHumanによる承認・決裁を必要とする事項、Human-only事項、例外承認および決裁記録の扱いを定める。

## 第2条 決裁の基本原則

1. AIが遂行可能な通常業務を、単にHuman確認が安心という理由で決裁事項へ格上げしない。
2. 決裁は、権限・法的責任・財務責任・本人性・物理操作・不可逆性その他、人間に留保すべき理由が具体的に存在する事項に限定する。
3. Human GateはTask全体ではなく、現在評価中の具体的な遷移またはAcceptance Criterion単位で適用する。
4. 後工程にのみ必要なHuman-only条件を、前工程の停止条件へ拡大しない。
5. 既存の明示的な決裁・承認GateをAIの推測だけで解除しない。

## 第3条 Owner決裁事項

次の事項は、Ownerの明示的な決裁を必要とする。

1. 規程の制定、改廃および恒久的なPolicy変更。
2. 組織上の役割、Repository別merge authorityその他の職務権限の新設・恒久変更・取消し。
3. 従量課金API、追加credit、plan upgrade、購入、支払その他の新たな費用負担を伴う行為。
4. 契約、法的義務、対外的な約束、財務責任または事業責任を伴う判断。
5. 本人確認、アカウント所有者権限、credential発行、権限付与等、Owner本人の権限を要する行為。
6. 重大な不可逆操作、データ破壊、公開・削除その他、回復不能または高影響の行為で現行規程に自律実行権限が定められていないもの。
7. Product / 事業の上位目的、重要なSuccess Metric、事業優先順位その他、AIに委任されていない経営判断。

## 第4条 Human-only事項

Human-only事項は、AIが接続手段や推論で代替できない事項に限定する。代表例は次のとおりとする。

1. AIが実行できない実機・物理操作または物理世界の観察。
2. 本人性、法的主体性、契約主体性またはアカウント所有者としての行為。
3. 支払、購入、契約、本人確認、credential受領その他のHuman権限行為。
4. 実ユーザーによる主観評価、対人インタビューその他、人間本人の反応を証拠とする評価。
5. 法的・財務的・経営的責任をHumanが負うべき決裁。
6. 現行規程でHuman承認を明示的に要求する不可逆または高影響操作。

Notion、GitHub、CI、既存記録その他の接続可能な情報からAIが直接確認できる事項はHuman-onlyとしない。

## 第5条 Human Gate判定

Human Requestの作成またはHuman理由によるBlocked遷移の前に、担当主体は少なくとも次を確認する。

1. 必要な証拠をNotion、GitHub、CI、既存Feedback等から検索したか。
2. Acceptance Criteriaを個別に `AI-verifiable` / `Human evidence already exists` / `Human-only` に分類したか。
3. AI-verifiableな項目を先に実行・確認したか。
4. 残ったHuman-only事項が、**現在の遷移**の必須条件か、後工程だけの条件かを確認したか。
5. Humanへ依頼する範囲を、残ったHuman-only事項だけに最小化したか。

「AIでできない理由を具体的に説明できない」事項は、Human Gateとして扱わない。

## 第6条 既存承認Gateの扱い

1. Accountable Reviewer、Ownerその他の権限者が、特定条件を現在の遷移の必須Gateとして明示した場合、そのGateは同等以上の権限者が明示的に改訂するまで有効とする。
2. AIは、一般論や後工程との混同を理由に既存Gateを独自解除してはならない。
3. 逆に、明示されていない後工程のHuman-only条件を現在の遷移へ勝手に前倒ししてはならない。

## 第7条 一時的例外

Ownerは、特定Task、Repository、操作、期間または条件に限定して、規程上の通常権限に対する一時的例外を承認できる。

例外承認には、少なくとも次を記録する。

1. 対象となるTask / Repository / 操作。
2. 通常ルールから何を変更するか。
3. 例外を必要とする理由。
4. 有効期間または終了条件。
5. 必要な追加品質条件またはリスク低減策。

例外は、明記された範囲を超えて一般化しない。

## 第8条 決裁記録

1. 重要な決裁はNotion Decisionまたは対象Taskに、結論、理由、対象範囲および日時を記録する。
2. GitHub成果物の改定を伴う場合は、PR / commit履歴を決裁の実装証跡として残す。
3. Decisionは判断履歴であり、それ自体を恒久Policyの正本としない。
4. 恒久的なPolicy変更は、該当する規程本文へ反映して初めて改定完了とする。

## 第9条 Ownerの直接指示

Ownerの最新の明示指示が既存の下位文書または古い記録と競合する場合、その具体的事項についてはOwner指示を優先する。

ただし、恒久的な制度変更である場合は、担当主体が速やかに該当規程・基準・手順を同期し、長期間の二重ルール状態を残さない。

## 第10条 決裁不要事項

次の事項は、現行Task・規程・職務権限の範囲内であれば、原則としてOwner決裁を不要とする。

1. 可逆的な情報取得、分析、設計、実装、テスト、文書修正。
2. Task範囲内のNotion / GitHub運用更新。
3. 既存規程に従うPR作成、レビュー依頼、修正、merge。
4. AI間の通常の引継ぎ、担当変更、Reviewerフェイルオーバー。
5. 既に承認済みの目的・予算・権限内での通常執行。

不要な決裁Gateを追加して自律実行を止めることは、統制強化ではなく運用上の欠陥として扱う。
